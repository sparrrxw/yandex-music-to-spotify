# План: локальный сервис переноса медиатеки из Яндекс Музыки в Spotify

_Актуально на 16 ноября 2026 года._

## 1. Цель

Локальное приложение (работает на компьютере пользователя, открывается в браузере по `http://127.0.0.1:8888`), которое:

1. Забирает из Яндекс Музыки все лайкнутые треки (позже: плейлисты, альбомы, артистов).
2. Находит каждый трек в Spotify с оценкой уверенности совпадения.
3. Показывает спорные и ненайденные треки для ручной проверки.
4. Сохраняет найденное в Spotify на выбор: **как лайки** («Любимые треки»), **в плейлист** или в оба места.
5. Умеет продолжать работу после обрыва или исчерпания квоты (перенос может растянуться на несколько дней).

## 2. Что изменилось в 2026 году и почему это важно

### Spotify Web API (главное ограничение)

| Изменение | Дата | Что значит для нас |
|---|---|---|
| Development Mode требует **Spotify Premium** у владельца приложения | 11.02 (новые) / 09.03.2026 (все) | Нужен Premium-аккаунт, чтобы зарегистрировать своё приложение |
| До **5 пользователей** на Client ID | то же | Для личного использования хватает |
| Extended Quota Mode — только для организаций | — | Публичный сервис «для всех» на своём Client ID сделать нельзя, только личный/для друзей |
| `PUT /me/tracks` удалён → **`PUT /me/library`** (до **40** URI за запрос, `spotify:track:...`) | 02.2026 | Использовать новые эндпоинты, старые библиотеки могут ловить 403 |
| `POST /users/{id}/playlists` → **`POST /me/playlists`** | 02.2026 | То же |
| `/playlists/{id}/tracks` → **`/playlists/{id}/items`**, поле `track` → `item` | 02.2026 | То же |
| `GET /tracks` (пакетная загрузка) удалён | 02.2026 | Не опираться на пакетные запросы |
| `GET /search`: `limit` максимум **10** (было 50) | 02.2026 | Поиск дороже, нужно аккуратно строить запросы |
| `external_ids` (ISRC) у трека — удаление **отменено** | 03.2026 | ISRC в ответах Spotify доступен |
| Refresh-токен живёт **6 месяцев** с момента авторизации | 06–07.2026 | Для разового переноса неважно, но обрабатывать `invalid_grant` |
| Общая дневная квота на аккаунт разработчика, ответ `429` с `reason: QUOTA_EXCEEDED`, сброс примерно через ~22–23 ч | 07.2026 | **Перенос большой медиатеки займёт несколько дней.** Нужны кэш, очередь и возобновление |

Точные числа дневной квоты Spotify не публикует. По сообщениям разработчиков, ограничение срабатывает примерно на тысячах запросов в сутки. Закладываемся на консервативный бюджет (например, 1000 поисковых запросов в день, настраивается).

### Яндекс Музыка

* Официального публичного API нет. Стандарт де-факто: неофициальная Python-библиотека **`yandex-music`** (MarshalX), актуальная версия **3.2.2 от 10.10.2026**, то есть проект живой.
* Нужен OAuth-токен аккаунта. Получение токена неофициальное (через OAuth-приложение клиента Яндекс Музыки или расширение браузера). Это серая зона ToS, но для чтения своей же медиатеки риск минимальный.
* Официальная альтернатива: архив личных данных через **Яндекс ID → Данные → Данные на сервисах → «Заказать архив»** (JSON/CSV/XML, ожидание от суток до 30 дней). Полнота данных Музыки в архиве не гарантирована, поэтому это запасной вход.
* ISRC в ответах API Яндекса обычно отсутствует, поэтому основной матчинг идёт по «артист + название + длительность + альбом».

### Spotify и Россия

Spotify в России недоступен, нужен зарубежный аккаунт (и Premium для режима разработчика). Возможно, API Spotify придётся вызывать через VPN. Приложение должно позволять указать прокси.

## 3. Все доступные способы и их сравнение

| Способ | Лайки → лайки | Надёжность | Легальность / ToS | Сложность для пользователя | Качество матчинга | Лимиты и цена |
|---|---|---|---|---|---|---|
| **A. Встроенный импорт Spotify** («Ваша медиатека → Импорт своей музыки», работает на движке TuneMyMusic, с ноября 2025) | Нет, создаёт плейлисты | Высокая | Официально | Минимальная | Средняя, без ручной правки | Бесплатно. **Поддержка Яндекс Музыки как источника не подтверждена**, проверить в приложении |
| **B. TuneMyMusic** (веб) | Частично (в плейлист; «любимые» есть в платных) | Высокая | Легально (у них свои ключи) | Низкая | Средняя, можно исправлять вручную | Бесплатно до 500 треков, дальше подписка |
| **C. Soundiiz** | Да (Premium) | Высокая | Легально | Низкая | Хорошая | Бесплатный тариф с ограничениями, перенос «любимых» и больших объёмов в Premium (цену уточнить на сайте) |
| **D. FreeYourMusic** | Да | Высокая | Легально | Низкая | Хорошая | Бесплатно 1 плейлист до 100 треков, дальше от 14,99 € за 3 мес; нужна зарубежная карта |
| **E. MusConv** | Да | Средняя | Легально | Низкая | Средняя | Платно |
| **F. Открытые скрипты на GitHub** (yandex2spotify и аналоги) | Да | **Низкая**: многие сломаны миграцией Spotify Feb 2026 (403 на старых эндпоинтах) | Серая зона на стороне Яндекса | Средняя/высокая | Низкая/средняя (простой поиск) | Бесплатно, упираются в квоту |
| **G. Свой локальный сервис** (этот план) | **Да, и лайки, и плейлист** | Высокая, если сделать возобновление | Серая зона на стороне Яндекса (неофициальный API), со стороны Spotify официально | Средняя (один раз создать приложение в Spotify Dashboard и получить токен Яндекса) | **Лучшая**: свой скоринг, транслитерация, ручная проверка | Бесплатно, но нужен Spotify Premium; квота растягивает перенос на дни |

**Вывод.** Если медиатека небольшая и не важно, лайки это или плейлист, проще всего попробовать встроенный импорт Spotify или TuneMyMusic. Если нужен полный контроль (точный матчинг русскоязычных треков, перенос именно в «Любимые», порядок лайков, отчёт о ненайденном), лучший вариант это **свой локальный сервис (G)**, а сторонние сервисы служат запасным путём через экспорт CSV.

## 4. Архитектура локального сервиса

```
┌────────────────────────────── компьютер пользователя ──────────────────────────────┐
│                                                                                    │
│  Браузер  ⇄  FastAPI (127.0.0.1:8888)                                               │
│                 │                                                                  │
│                 ├── Яндекс-коннектор (yandex-music)  ──► Яндекс Музыка             │
│                 ├── Spotify-коннектор (httpx, PKCE)  ──► Spotify Web API            │
│                 ├── Матчер (rapidfuzz + транслитерация + скоринг)                   │
│                 ├── Планировщик задач (очередь, бюджет квоты, возобновление)        │
│                 └── SQLite (data/transfer.db): треки, кандидаты, статусы, кэш      │
│                                                                                    │
└────────────────────────────────────────────────────────────────────────────────────┘
```

### Стек

* **Python 3.12+**
* **FastAPI + Uvicorn**: локальный веб-сервер; UI на Jinja2-шаблонах + **htmx** (без отдельной сборки фронтенда).
* **yandex-music 3.2.x**: чтение лайков и плейлистов.
* **httpx**: собственный тонкий клиент Spotify под новые эндпоинты (`/me/library`, `/me/playlists`, `/playlists/{id}/items`) с правильной обработкой 429. Spotipy 2.26 тоже подходит, но свой клиент проще контролировать.
* **rapidfuzz**: нечёткое сравнение строк. **transliterate / unidecode**: транслитерация кириллицы (Spotify часто пишет русских артистов латиницей, и наоборот).
* **SQLite** (через `sqlite3` или SQLModel): всё состояние переноса.
* **keyring**: хранение токенов в системном хранилище Windows, а не в открытом файле.
* Упаковка: `uv` / `pip` + скрипт `run.bat`; позже по желанию **PyInstaller** в один `.exe`.

### Модель данных (SQLite)

* `source_tracks`: id Яндекса, название, версия (remix, live), артисты, альбом, год, длительность, `liked_at`, позиция в лайках, ISRC (если есть).
* `candidates`: source_track_id, spotify_uri, название/артисты/альбом/длительность/ISRC из Spotify, score, метод (isrc / точный / нечёткий).
* `matches`: source_track_id, выбранный spotify_uri, статус (`auto`, `needs_review`, `manual`, `not_found`, `skipped`).
* `transfer_ops`: что и куда записано (library / playlist_id), статус, ошибка, время.
* `search_cache`: запрос → ответ Spotify (чтобы повторный запуск не тратил квоту).
* `quota_log`: счётчик запросов за сутки, время блокировки по `Retry-After`.

### Алгоритм матчинга

1. **Нормализация**: нижний регистр, удаление `feat./ft.`, скобок с `Remastered`, `Original Mix` и т.п.; сохранение значимых пометок (`Remix`, `Live`, `Acoustic`) отдельным полем.
2. **Запросы к Spotify** (каждый максимум 10 результатов, идём до первого уверенного совпадения):
   1. `isrc:XXXX`, если ISRC известен;
   2. `track:"<название>" artist:"<главный артист>"`;
   3. то же, но с транслитерацией названия/артиста;
   4. свободный запрос `<артист> <название>`.
3. **Скоринг кандидата** (0–100): сходство названия (40), артистов (30), длительность в пределах ±3 с (20, с плавным штрафом до ±10 с), альбом (10); штраф, если совпадает «Remix/Live» у одного и нет у другого.
4. **Пороги**: ≥ 85 → `auto`; 60–85 → `needs_review` (в UI показываем 3 лучших варианта); < 60 → `not_found` (кнопки «найти вручную» по ссылке или поиску, «пропустить»).

### Запись в Spotify

* **Лайки**: `PUT /me/library?uris=...` пачками по 40. Чтобы сохранить порядок «самые новые сверху», добавляем **от самого старого лайка к самому новому** (Spotify ставит `added_at` = время добавления). Перед записью проверяем `GET /me/library/contains`, чтобы не дублировать.
* **Плейлист**: `POST /me/playlists` (приватный, название вида «Яндекс Музыка: Мне нравится»), затем `POST /playlists/{id}/items` пачками (по 100, уточнить лимит на практике).
* Режим **dry-run**: всё посчитать и показать, ничего не записывая.

### Работа с квотой

* Глобальный ограничитель скорости (например, 1 запрос в 0,3–0,5 с) + дневной бюджет из настроек.
* На `429` с `Retry-After` до минуты: подождать и повторить. На `QUOTA_EXCEEDED` или долгом `Retry-After`: сохранить время разблокировки, поставить задачу на паузу, показать в UI «продолжим после 14:30 завтра».
* Все этапы идемпотентны: повторный запуск пропускает уже найденное и уже записанное.

## 5. Пользовательский сценарий (экраны)

1. **Настройка**: ввод Spotify Client ID (с подсказкой, как создать приложение в Spotify Developer Dashboard с Redirect URI `http://127.0.0.1:8888/callback`), вход в Spotify (PKCE), ввод/получение токена Яндекса, прокси (опционально).
2. **Импорт из Яндекса**: кнопка «Загрузить лайки», счётчик треков.
3. **Сопоставление**: прогресс-бар, остаток квоты, статистика (найдено автоматически / на проверку / не найдено).
4. **Проверка**: таблица спорных треков с вариантами, прослушиванием превью (ссылка в Spotify), ручным выбором.
5. **Перенос**: выбор «в лайки», «в плейлист» или оба, dry-run, запуск.
6. **Отчёт**: экспорт в CSV ненайденного и итогов (этот CSV можно скормить TuneMyMusic как запасной путь).

## 7. Риски

* **Квота Spotify** непрозрачна: перенос 3–5 тысяч треков может занять 2–5 дней. Решается кэшем и возобновлением.
* **Spotify снова поменяет API** (в 2026 году менял трижды). Весь доступ к Spotify держим в одном модуле `spotify_client.py`.
* **Яндекс может сломать неофициальный API или способ получения токена.** Следим за обновлениями `yandex-music`; запасной вход через архив Яндекс ID или ручной CSV.
* **Каталожные различия**: часть русскоязычной музыки отсутствует в Spotify. Ожидаемо 5–20% «не найдено», они попадут в отчёт.
* **Блокировки по региону**: возможно, понадобится VPN для Spotify; Яндекс может не пускать с зарубежного IP. В настройках можно задать прокси отдельно для каждой стороны.
